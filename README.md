# ufz-galaxy-tools

Tool lists for the Galaxy instance at [galaxy.ufz.de](https://galaxy.ufz.de), organized as code.

The repository keeps, for every tool panel section of the instance, a small YAML file listing the
tools that should be installed, plus a `.lock` file that pins the exact Tool Shed revisions.
`make lint` validates the lists, `make fix` brings the lock files back in sync, `make install`
installs the pinned revisions into a Galaxy instance.

This repository follows the
[galaxy_tools_management_template](https://github.com/martenson/galaxy_tools_management_template)
layout (one directory per Galaxy instance, one file per tool panel section).

## Layout

```
galaxy.ufz.de/
├── sections/
│   ├── assembly.yml            # human edited: section label + tools (name, owner)
│   ├── assembly.yml.lock       # generated: revisions + install flags + section id
│   └── ...
└── schema/
    └── .schema.yml             # pykwalify schema, enumerates the valid section ids
scripts/                        # helper scripts used by the Makefile and the CI workflows
.github/workflows/              # lint / fix / update / install automation
bioinf-ufz/                     # ansible playbooks (separate concern, not managed here)
```

Everything the Makefile touches lives under `<instance>/sections/`. The instance directory is
`galaxy.ufz.de` and is the default value of `INSTANCE`, so `make lint` works with no arguments.

### Section file (hand edited)

```yaml
tool_panel_section_label: Assembly
tools:
- name: spades
  owner: nml
- name: megahit
  owner: iuc
```

### Lock file (generated by `make fix`)

```yaml
install_repository_dependencies: true
install_resolver_dependencies: false
install_tool_dependencies: false
tools:
- name: megahit
  owner: iuc
  revisions:
  - 2a822228b2ba
  tool_panel_section_id: assembly
  tool_panel_section_label: Assembly
```

The `tool_panel_section_id` written into the lock file is the slugified section label (the same
string as the file name without `.yml`). If a section id has to differ from the slug — e.g. to match
a pre-existing panel on the instance — add an explicit top-level `tool_panel_section_id:` to the
section file; `fix_lockfile.py` then uses it instead of generating one.

## Requirements

Python 3.8+ and `make`. Install the Python dependencies into a virtual environment:

```
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
```

`mercurial` and `galaxy-tool-util` are only needed for `make fix-outdated`; linting, fixing and
updating only require `bioblend`, `pykwalify` and `PyYAML`. The CI workflows therefore install the
small subset explicitly.

## Common tasks

| Task | Command |
|---|---|
| Lint everything | `make lint` |
| Sync lock files after editing a section file | `make fix` |
| Update one tool to its latest revision | `make update-repo REPO_NAME=<repo>` |
| Update all tools of one owner | `make update-owner REPO_OWNER=<owner>` |
| Update all tools | `make update-all` |
| Repair non-installable revisions (slow) | `make fix-outdated` |
| Install the pinned revisions into Galaxy | `make install` (needs `GALAXY_API_KEY`) |

`make help` lists the targets.

### Adding a tool

1. Add `- name: <tool>` / `owner: <owner>` to the right `galaxy.ufz.de/sections/<section>.yml`.
2. Optionally add an explicit `revisions:` (otherwise `make fix` picks the latest installable one).
3. `make fix` to create/extend the lock file.
4. `make lint` to validate; open a PR.

### Adding a section

1. Create `galaxy.ufz.de/sections/<section_id>.yml` with a `tool_panel_section_label:` and its tools.
2. Add `<section_id>` to the `tool_panel_section_id` enum in `galaxy.ufz.de/schema/.schema.yml`.
3. `make fix && make lint`.

### Removing a tool

Delete the entry from the section file and run `make fix`; the lock file entry disappears. Removing
the tool from the *instance* is a separate, manual operation.

## Automation

| Workflow | Trigger | Effect |
|---|---|---|
| `lint.yml` | pull request | `make lint` — fails on unknown tools, schema violations, unpinned revisions |
| `fix.yml` | push to `main` | `make lint && make fix`, then a PR with the regenerated lock files |
| `cron_update.yml` | weekly (Wed 07:07) | `make lint && make update-all`, then a PR |
| `dispatch_lint.yml` | manual | lint, for the instance selected in the dispatch form |
| `dispatch_update.yml` | manual | `make lint && make update-all`, then a PR |
| `dispatch_install.yml` | manual only | `make install` with the `GALAXY_API_KEY` secret |

All automated changes reach `main` through pull requests, never by a direct push.

## Installation is manual

This repository is not used to keep the instance in sync automatically: nothing is installed on a
schedule. Installing into Galaxy means

* running `GALAXY_API_KEY=<admin key> make install` locally, or
* running the `Dispatch Install` workflow (requires the `GALAXY_API_KEY` repository secret).

Both install the revisions pinned in the lock files (`ephemeris shed-tools install`,
`install_repository_dependencies: true`, `install_resolver_dependencies: false`).

## Notes

* Section ids are derived from the section labels. Two label variants that historically differed
  only by a trailing space (`Metagenomics `, `Proteomics `) were merged during the migration to this
  layout.
* `scripts/yaml_check.py` looks repositories up by name *and* owner, so a wrong owner is caught at PR
  time, and it tolerates a missing lock file for brand new sections.
* `scripts/fix_outdated.py` replaces non-installable revisions; it clones Tool Shed repositories
  (`hg`) and is deliberately not part of CI.
* `bioinf-ufz/` contains ansible playbooks for the UFZ infrastructure and is out of scope here.
